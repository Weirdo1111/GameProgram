# AI Usage Statement

## Project

**Zombie Storm**

This statement explains how AI tools were used during the development and documentation of Zombie Storm. AI support was used as an assistant for production, refinement, and presentation. It did not replace my authorship of the game concept, gameplay design, testing process, or main project decisions.

## Summary of AI use

AI was used in three main areas:

1. Visual asset polishing and generation support.
2. Coding assistance and explanation support.
3. Documentation drafting, editing, and organization support.

All AI-assisted work was reviewed, selected, edited, and integrated by me before being included in the final project.

## Visual asset support

Some project-specific visual assets were generated or polished with AI image generation after I had already planned the visual direction.

The following visual elements began from my own sketches, layout ideas, or design direction, then were refined with AI support:

- Main menu cover image.
- Skill card UI artwork.
- Player character presentation.
- Player idle, movement, and hurt-related art direction.
- Opening story images.
- Fire Spirit image.
- Upgrade card images.

My role included:

- Creating the original concept and visual direction.
- Making sketches and layout ideas.
- Selecting usable generated outputs.
- Cropping, editing, preparing, and integrating images into Unity.
- Deciding how each asset should support gameplay, UI readability, and story presentation.

AI image generation was used as a production and polishing tool. The final choices, editing decisions, and game integration were my responsibility.

## Coding support

AI coding assistance was used during development as a support tool for explanation, refinement, debugging suggestions, and documentation of code structure.

The following areas were my own design and implementation responsibility:

- Original game concept and story.
- Main gameplay loop.
- Player movement and survival structure.
- Skill roles and upgrade design.
- Enemy roles, boss structure, and difficulty direction.
- Numerical balance direction for movement, skills, enemies, bosses, and upgrades.
- Object pooling idea and key pooling code.
- Testing process and gameplay iteration.
- Asset selection and integration decisions.

AI assistance helped with improving clarity, reviewing implementation ideas, organizing code explanations, and refining some development work. Any generated or suggested code was reviewed and adapted before use.

## Documentation support

AI was used to help draft, organize, and refine written documentation, including report-style explanations, asset-use wording, and submission guidance.

The content was based on my actual project, my design decisions, my testing process, and my development contribution. I reviewed and edited the documentation so it matched the final game.

Documentation supported by AI includes:

- Design explanation wording.
- Report structure and professional phrasing.
- Asset-use clarification.
- Submission form wording.
- README improvement suggestions.

## What was not AI-generated

The following were not simply generated by AI:

- The original game idea.
- The story premise.
- The intended player experience.
- The skill system concept.
- Enemy and boss design direction.
- Main gameplay balance direction.
- Object pooling decision and key implementation plan.
- Step-by-step testing and debugging process.
- Final decisions about what to include in the game.

AI support was used to assist the development process, but the project remained my own authored coursework submission.

I confirm that AI tools were used responsibly as support tools. I reviewed the outputs, made the final design and implementation decisions, and integrated the work into the project myself.
